# 2026-09-08 UI 모달·버튼 편집 도구 후속 작업

## 1. 작업 목적

버튼 크기와 텍스트 크기 등을 구현자가 임의로 반복 조정하는 대신, 제작자가 실제 화면을 보면서 직접 맞출 수 있는 UI 편집 도구를 만든다.

현재의 `PlayUiTunerPanel`은 공통 슬라이더 실험 도구일 뿐이며, 요청한 “전체 모달 및 버튼 상세 편집” 기능으로 간주하지 않는다.

## 2. 현재 구현 상태와 한계

### 현재 가능한 기능

- 설정 모달에서 `Credit`을 길게 눌러 하단 패널을 연다.
- 글자 크기, 모달 여백·폭·위치, 버튼 폭·글자 위치 등 일부 공통값을 슬라이더로 바꾼다.
- 값은 `SharedPreferences`에 자동 저장된다.
- 현재 값을 JSON으로 복사하거나 기본값으로 초기화할 수 있다.

### 현재 문제점

- 진입 방법이 숨겨져 있어 제작 도구로 사용하기 어렵다.
- 편집 대상 모달과 버튼을 선택할 수 없다.
- 실제 모달을 전환하며 확인하는 미리보기가 없다.
- 모든 대상에 같은 전역값이 적용되고, 모달별 개별값이 없다.
- 버튼 높이는 이미지 비율로 자동 계산돼 제작자가 직접 조절할 수 없다.
- 색상, 배경 투명도, 버튼 내부 여백 등 상세 설정이 부족하다.
- 일부 전역 토큰은 모달 밖 일반 화면에도 영향을 준다.
- 웹에서는 브라우저 저장과 JSON 복사만 가능하며 소스 코드는 자동 변경되지 않는다.
- `ParchmentModal`을 사용하지 않는 마을 `AlertDialog`와 레벨 로딩 `Card`는 편집 범위 밖이다.

## 3. 편집 대상

### 1차 구현 대상

공통 `ParchmentModal` 계열 전체를 우선 지원한다.

1. 설정 모달
2. 크레딧 모달
3. 게임 종료 확인 모달
4. 퍼즐 포기 확인 모달
5. 완료 보상 모달
6. 체험판 마지막 판 Google Play 안내 모달

함께 편집할 버튼 계열은 다음과 같다.

- `ParchmentModalButton`
- `OvalImageButton`
- 모달 안에 배치되는 1개·2개 버튼 행의 간격과 정렬

### 2차 통합 대상

- 마을 화면의 기본 `AlertDialog`
- 레벨 선택 화면의 로딩 `Card`

두 예외 UI는 1차 도구를 안정화한 뒤 공통 모달 체계로 이전한다.

## 4. 노출 정책

- Google Play 앱 빌드에는 편집 도구를 노출하지 않는다.
- 일반 공개 웹 데모 화면에도 편집 버튼을 상시 노출하지 않는다.
- 별도 컴파일 플래그 `UI_TUNER=true`인 제작자용 웹 빌드에서만 설정 화면에 명시적인 `UI 편집` 진입 버튼을 표시한다.
- 기존 `Credit` 길게 누르기 방식은 제거하거나 보조 진입 방식으로만 남긴다.
- 배포는 사용자의 명시적인 지시가 있을 때만 수행한다.

## 5. 목표 편집 화면

편집 화면은 실제 미리보기와 설정 패널을 동시에 제공해야 한다.

### 대상 선택

- 공통 설정
- 설정
- 크레딧
- 게임 종료
- 퍼즐 포기
- 완료 보상
- 체험판 종료
- 타원형 버튼

### 모달 설정

- 최소·최대 너비
- 바깥 가로·세로 여백
- 내부 가로·세로 여백
- 가로·세로 위치
- 제목·본문·버튼 사이 간격
- 배경 이미지와 콘텐츠 영역의 맞춤 방식
- 배경 오버레이 색상과 투명도

### 버튼 설정

- 최소·최대 너비
- 높이 또는 높이 배율
- 가로·세로 내부 여백
- 버튼 사이 간격
- 글자 크기
- 글자 가로·세로 위치
- 이미지 양끝 보호 영역 비율
- 한 줄 넘침 처리 결과

### 텍스트 설정

- 제목, 본문, 라벨, 버튼, 보조문구 크기
- 줄 높이
- 정렬
- 최대 줄 수와 넘침 방식

### 작업 명령

- 선택 대상 초기화
- 공통값 초기화
- 전체 초기화
- 자동 저장
- JSON 내보내기
- JSON 가져오기
- 현재값 복사

## 6. 값 적용 구조

공통값과 모달별 개별값을 분리한다.

1. `PlayUiDefaults`: 코드 기본값
2. `PlayUiCommonTune`: 모든 모달에 적용되는 제작자 공통값
3. `PlayUiTargetTune`: 특정 모달 또는 버튼에만 적용되는 덮어쓰기 값
4. 렌더링 시 `기본값 → 공통값 → 대상별 값` 순서로 병합한다.

대상은 문자열을 직접 흩어 쓰지 않고 열거형 또는 고정 ID로 관리한다. 예시는 `settings`, `credits`, `exitGame`, `giveUp`, `completionReward`, `trialEnd`, `ovalButton`이다.

기존 `PlayUi` 전역 접근자를 무조건 확장하지 않는다. 모달 밖 화면에 값이 새지 않도록 대상 프로필을 `ParchmentModal`과 버튼 생성 시 명시적으로 전달한다.

## 7. 저장 및 반영 방식

- 제작 중 변경값은 브라우저 `SharedPreferences`에 즉시 저장한다.
- 새로고침 후에도 같은 제작자용 빌드에서 복구돼야 한다.
- JSON 가져오기와 내보내기는 동일한 스키마를 사용한다.
- 웹 브라우저가 저장소 소스 파일을 직접 수정할 수 있다고 가정하지 않는다.
- 최종 확정값은 JSON을 복사해 저장소의 기본 설정 파일로 반영하고 코드 검증 후 커밋한다.
- JSON에는 스키마 버전을 포함해 이후 필드 추가 시 이전 값도 읽을 수 있게 한다.

## 8. 구현 순서

### 단계 1: 데이터 구조 정리

- 기존 전역 `PlayUiTune` 값을 공통값과 대상별 값으로 분리한다.
- 버튼 높이, 내부 여백, 줄 높이, 오버레이 투명도 필드를 추가한다.
- 기존 `play_ui_tune_v1` 저장값을 새 스키마로 마이그레이션한다.

### 단계 2: 제작자용 편집 화면

- `UI_TUNER=true` 조건을 추가한다.
- 설정 화면에 명시적인 진입 버튼을 만든다.
- 대상 선택, 실제 미리보기, 설정 패널을 한 화면에 배치한다.
- 작은 웹 화면에서도 미리보기와 컨트롤이 서로 가리지 않도록 접기 또는 탭 전환을 제공한다.

### 단계 3: 모달·버튼 연결

- 여섯 개 `ParchmentModal`에 대상 ID를 연결한다.
- `ParchmentModalButton`과 `OvalImageButton`에 편집값을 연결한다.
- 버튼 높이를 폭의 고정 종횡비에서 분리하되 이미지가 과도하게 찌그러지지 않도록 허용 범위를 둔다.

### 단계 4: 저장·가져오기·내보내기

- 자동 저장과 새로고침 복구를 확인한다.
- JSON 가져오기, 복사, 대상 초기화, 전체 초기화를 구현한다.
- 잘못된 JSON이나 범위를 벗어난 값은 거부하거나 안전 범위로 제한한다.

### 단계 5: 하네스와 수동 검증

- 대상별 값이 다른 모달에 새지 않는지 검증한다.
- 공통값과 대상값의 병합 우선순위를 검증한다.
- 저장·복구 및 JSON 왕복을 검증한다.
- 앱 기본 빌드와 일반 웹 데모에서 편집 진입점이 보이지 않는지 검증한다.
- 실제 브라우저에서 한국어와 영어 긴 문구, 1버튼과 2버튼 모달을 확인한다.

## 9. 완료 조건

다음 조건을 모두 만족해야 완료로 본다.

- 제작자가 코드 수정 없이 버튼 너비·높이·글자 크기·텍스트 위치를 직접 조절할 수 있다.
- 여섯 개 모달을 선택해 실제 형태에 가까운 미리보기를 볼 수 있다.
- 공통값과 모달별 개별값을 구분해 적용할 수 있다.
- 설정 변경이 미리보기에 즉시 반영된다.
- 새로고침 후 값이 유지된다.
- JSON 내보내기와 가져오기 결과가 일치한다.
- 선택 대상 초기화와 전체 초기화가 구분된다.
- 제작자용 편집 기능이 Google Play 앱과 일반 공개 웹 데모에 노출되지 않는다.
- 기존 모달과 버튼 동작, BGM 게이트, 마지막 판 안내 모달 테스트가 모두 통과한다.

## 10. 선행 변경 보존 사항

다음 웹 오디오 수정은 커밋 `9f25206`으로 보존돼 있다. 후속 작업을 시작할 때 덮어쓰거나 누락하지 않는다.

- 웹 BGM 게이트 배경을 `0x9907152F` 60% 반투명으로 변경
- 뒤쪽 콘텐츠는 보이되 포인터 입력은 계속 차단
- `BGM OFF` 포인터 다운 시 BGM과 SFX를 모두 즉시 비활성화
- 늦게 완료된 SFX 설정 로드가 사용자의 OFF 선택을 덮어쓰지 못하도록 revision 보호 추가
- Pages 배포 하네스에 `web_audio_preference_harness_test.dart` 추가

현재 검증 결과는 웹 데모 하네스 8개 통과, 관련 정적 분석 문제 없음이다. 단, 이 커밋은 웹 전용 내용인데 현재 `main`에 잘못 올라가 있으며 `pages`에는 반영되지 않아 공개 배포되지 않았다.

## 11. 예상 작업량

- 1차 편집 도구와 여섯 개 모달 연결: 약 1.5~2시간 분량
- 예외 `AlertDialog`와 로딩 `Card` 통합: 1차 안정화 후 별도 진행

시간보다 완료 조건과 회귀 테스트 통과를 우선한다.

## 12. 브랜치 운영 규칙과 정정 작업

### 확정된 소유 범위

- `main`: Google Play 앱 및 앱 관련 작업
- `pages`: 웹 데모 전용 구현과 GitHub Pages 배포
- `web-demo-next` 등의 별도 원격 브랜치: 검증 중이거나 아직 배포 승인을 받지 않은 웹 데모 작업

웹 전용 변경을 다른 PC에서 이어서 작업해야 한다는 이유로 `main`에 올리지 않는다. `pages`는 푸시 즉시 자동 배포되므로, 배포 전 원격 보존이 필요하면 반드시 별도 웹 작업 브랜치를 사용한다.

### 현재 상태

- `577ad99`: UI 모달·버튼 편집 도구 후속 문서이며 `main`에 유지한다.
- `9f25206`: 반투명 웹 BGM 게이트, `BGM OFF → SFX OFF`, 웹 하네스 변경이며 `pages` 소유 내용이다.
- `9f25206`은 현재 `main`에 잘못 포함돼 있다.
- `pages`는 `40a864b` 상태이므로 `9f25206` 변경은 아직 공개 웹에 배포되지 않았다.

### 다음 작업 시작 시 우선 정정

1. `9f25206`을 `web-demo-next` 원격 작업 브랜치에 보존한다.
2. `main`에서는 `9f25206`을 되돌려 앱 브랜치에서 웹 전용 변경을 제거한다.
3. `pages`는 사용자의 명시적인 배포 지시 전까지 변경하지 않는다.
4. 배포 지시 후 `web-demo-next`의 검증된 커밋을 `pages`에 반영하고 Actions 결과를 확인한다.

되돌리기는 커밋 이력을 삭제하는 강제 재설정이 아니라 별도 revert 커밋으로 수행해 작업 기록을 보존한다.
