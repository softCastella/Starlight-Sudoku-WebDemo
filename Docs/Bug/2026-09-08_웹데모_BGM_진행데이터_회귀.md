# 웹 데모 BGM·진행 데이터 회귀 분석

- 작성일: 2026-09-08
- 대상: `https://softcastella.github.io/Starlight-Sudoku/`
- 배포 브랜치: `pages`
- 확인 시각 기준 공개 파일 Last-Modified: 2026-09-08 00:06 KST

## 증상

1. 첫 화면의 BGM ON/OFF 게이트 배경이 단색으로 보인다.
2. 첫 접속에서 `BGM ON`을 눌러도 BGM이 바로 들리지 않는다.
3. 웹 데모를 Easy 5판으로 바꾼 뒤 진행 표시가 `10/5`로 보인다.
4. 웹 데모를 닫았다가 다시 열어도 이전 클리어 상태가 남는다.
5. 타이틀 버튼 SFX가 버튼 입력보다 늦게 들린다.

## 원인

### 1. 반투명 게이트 변경의 배포 누락

공개 `pages` 브랜치의 `WebAudioGate.backgroundColor`는 불투명한
`0xFF07152F`이다. 반투명 `0x9907152F` 변경은 커밋 `9f25206`에 있으나
`main`에만 반영되어 있고 공개 웹을 만드는 `pages`에는 포함되지 않았다.

따라서 이 증상은 브라우저 캐시나 Flutter 합성 문제가 아니라 배포 브랜치와
수정 브랜치가 어긋난 결과다.

### 2. BGM 스트리밍 시작과 첫 버퍼 지연

타이틀 BGM 파일 URL은 정상이다. 공개 Pages에서 이중 인코딩 URL
`1_Title_Lamplight%2520Grid.ogg`는 200을 반환하며 파일 크기는 730,479바이트다.
확인 시 콜드 요청은 약 0.85초가 걸렸다. 단일 인코딩 `%20` URL은 404이므로
현재 이중 인코딩 자체는 올바르다. Pages는 `Accept-Ranges: bytes`를 제공하며
0~65,535바이트 요청에 `206 Partial Content`로 정확히 65,536바이트만 응답했다.
따라서 전체 파일을 먼저 받지 않고 브라우저 네이티브 스트리밍으로 재생할 수 있다.

기존 HTML의 `<link rel="preload" as="audio">`와 `audio.load()`는 ON 선택 전에
음원 전송을 시작할 수 있어 웹 데모 정책에 맞지 않는다. 반대로 아무 상태 표시 없이
ON 직후 게이트를 닫으면, 콜드 네트워크의 첫 범위 요청과 첫 버퍼·디코딩 시간이
타이틀 화면에서 뒤늦게 들리는 지연처럼 보인다. 이는 Pages 장애가 아니라 스트리밍의
첫 버퍼 시간이 UI 전환과 분리되어 노출된 문제다.

### 3. 10판 진행값과 5판 설정의 혼합

`WEB_DEMO=true`는 표시 가능한 Easy 스테이지만 5개로 바꾼다. 기존
`stage_progress` 저장값을 변환하거나 지우지는 않는다. 10판 데모에서 Easy
1~10을 완료한 브라우저는 완료 집합 10개를 그대로 복원하고, UI는
`완료 집합 길이 / 현재 stageCount`를 표시하므로 `10/5`가 된다.

완료 개수를 현재 스테이지 수로 제한하는 방어 로직도 없어서 잘못된 저장값이
그대로 사용자 화면에 노출됐다.

### 4. 웹 데모에도 앱과 같은 영구 저장 정책 적용

`GameProgressStore`는 앱과 웹을 구분하지 않고 `SharedPreferences`에 별빛,
통계, 스테이지 진행, 이어하기, 스토리/체험판 안내 상태를 저장한다. 웹에서는
이 값이 브라우저의 영구 저장소에 남으므로 탭을 닫고 다시 열어도 클리어 상태가
복원된다. 현재 동작은 구현상 의도된 영구 저장이지만, 매 방문을 새 체험으로
시작해야 하는 공개 웹 데모 정책과 맞지 않는다.

### 5. 버튼 SFX의 웹 플러그인 지연

프로그램의 SFX 페이드는 재생 시작 후 200ms가 지난 뒤 적용되는 페이드아웃이므로
앞쪽 지연의 원인이 아니다. 웹에서도 `audioplayers`를 사용하면서 첫 입력 뒤
플레이어 생성, `stop()`, 볼륨 설정, AssetSource 준비를 순서대로 기다렸다. 버튼은
이 작업을 기다리지 않고 화면을 전환하므로 다음 화면에서 소리가 뒤늦게 들리는 것처럼
보였다.

## 수정 방침

1. `pages`에 반투명 게이트 변경을 포함한다.
2. 숨겨진 `<audio preload="none">`를 Flutter가 재사용하되 ON 전에는 음원을
   요청하지 않는다. ON 포인터 입력에서 `play()`를 직접 호출해 HTTP Range
   스트리밍을 시작하고, 첫 버퍼가 실제 재생을 시작할 때까지 게이트를 유지한다.
3. `WEB_DEMO=true` 진행 데이터는 탭 세션 단위로 운용한다.
   - 새 탭/브라우저로 데모를 열면 게임 진행만 초기화한다.
   - 같은 탭의 새로고침에서는 진행을 유지한다.
   - BGM/SFX 설정, 언어, 익명 사용자 ID는 게임 진행과 분리해 유지한다.
4. 완료 개수 표시는 현재 난이도의 스테이지 수를 넘지 않도록 상한을 둔다.
5. 세션 초기화, `10/5` 방지, HTML 오디오 선로딩 계약을 자동 테스트에 추가한다.
6. 웹 버튼 SFX는 `<audio preload="none">`를 재사용하고 포인터 다운에서 바로
   HTTP Range 스트리밍을 시작한다. 앞쪽 페이드는 추가하지 않고 기존 뒤쪽
   페이드아웃만 유지한다.

## 배포 전 확인 항목

- 시크릿 창 첫 진입에서 배경 뒤 타이틀 화면이 반투명하게 보인다.
- ON 전에는 BGM 네트워크 요청이 없고, ON 후에는 206 범위 요청으로 재생된다.
- 콜드 캐시에서는 첫 재생이 시작된 뒤 게이트가 닫힌다.
- 이전 10판 진행값이 있는 브라우저에서도 새 탭 첫 표시는 `0/5`다.
- 같은 탭 새로고침은 진행을 유지하고, 탭을 닫아 새로 열면 초기화된다.
- Easy 완료 표시는 어떤 저장값에서도 `5/5`를 넘지 않는다.
