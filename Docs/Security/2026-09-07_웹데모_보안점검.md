## 결론

현재 웹 데모는 정적 Flutter 웹 애플리케이션이다. 자체 서버, 데이터베이스, 로그인, 결제, 사용자 입력 폼이 없어 서버 침해와 SQL 인젝션에 해당하는 공격 표면은 작다.

코드와 배포 결과에서 즉시 악용 가능한 인젝션, 저장소에 포함된 비밀정보, 알려진 Dart/Flutter 의존성 취약점은 발견하지 못했다. 다만 모든 소프트웨어와 마찬가지로 보안 위험이 전혀 없다고 보장할 수는 없으며, 배포 변경 시 아래 항목을 다시 점검해야 한다.

## 웹 데모와 앱 빌드 구분

| 대상 | 브랜치·빌드 조건 | 제공 범위 |
| --- | --- | --- |
| GitHub Pages 웹 데모 | `pages`, `WEB_DEMO=true` | Easy 5판 |
| Google Play 체험판 | `main`, 기본 빌드 | Easy 10판 |
| 정식판 설정 | `GameBalance.isTrial=false`로 별도 준비 | Easy 20 / Normal 40 / Hard 50 |

GitHub Pages 워크플로는 `pages` 브랜치 푸시에만 자동 실행된다. `main` 푸시만으로 공개 웹은 변경되지 않는다.

## 공개 데이터와 저장 데이터

웹 빌드에 포함된 Dart/JavaScript 코드, 이미지, 폰트, 음원, 퍼즐 생성 규칙은 누구나 내려받을 수 있는 공개 데이터로 취급한다.

다음 정보는 브라우저 로컬 저장소에만 저장한다.

- 퍼즐 진행 상태
- StarLight와 통계
- 설정값
- 익명 로컬 사용자 ID
- 선택한 언어

현재 코드에서는 위 데이터를 자체 서버로 전송하지 않는다. 계정, 이메일, 전화번호, 위치, 결제정보를 수집하지 않는다.

## 인젝션 점검

### 언어 쿼리

랜딩과 웹게임은 `?lang=` 또는 `?locale=` 값을 읽는다. 입력 문자열을 그대로 HTML에 삽입하지 않고 한국어, 영어, 일본어, 중국어, 대만 중국어의 허용 목록으로 정규화한다.

- 랜딩 문구는 `textContent`와 고정된 번역 객체만 사용한다.
- 링크의 언어값은 `encodeURIComponent`로 인코딩한다.
- Flutter 쪽 언어값도 `Locale` 허용 목록으로 변환한다.
- `innerHTML`, `document.write`, `eval`, 동적 스크립트 삽입은 사용하지 않는다.

현재 구조에서 확인된 DOM 기반 XSS 경로는 없다.

### 서버·DB 인젝션

GitHub Pages는 정적 파일만 제공하며 프로젝트에 자체 API와 DB가 없다. 따라서 현재 배포 범위에는 SQL 인젝션, 서버 명령 인젝션, 서버 템플릿 인젝션 대상이 없다.

향후 점수 서버, 계정, 리더보드, 문의 폼을 추가하면 서버 입력 검증, 인증, 권한 확인, 요청 제한, 로그와 비밀정보 관리 항목을 새로 점검해야 한다.

## 비밀정보와 서명 파일

현재 추적 파일과 Git 기록에서 다음 항목은 발견되지 않았다.

- API 키와 액세스 토큰
- 비밀번호와 클라이언트 시크릿
- `key.properties`
- JKS·keystore·PEM·P12 파일
- Firebase 설정 파일
- `.env`와 기타 자격증명 파일

`.gitignore`는 서명 파일, 환경 파일, `secrets.json`, `api_keys.dart`를 제외하도록 설정되어 있다.

중요: Flutter 웹에 포함한 값은 난독화 여부와 관계없이 비밀이 아니다. 향후 API를 연결할 때 장기 비밀키를 Dart 코드, HTML, JavaScript 또는 GitHub Pages 파일에 넣지 않는다.

## HTTP와 브라우저 보안 상태

실제 배포 응답에서 확인한 내용:

- HTTPS 사용
- `Strict-Transport-Security` 적용
- GitHub Pages 정적 호스팅 사용
- `Content-Security-Policy` 없음
- `X-Content-Type-Options` 없음
- `X-Frame-Options` 없음
- `Referrer-Policy` 없음
- `Permissions-Policy` 없음

누락된 헤더는 현재 확인된 침해를 의미하지는 않지만 방어 심층화 항목이다. GitHub Pages는 사용자 지정 응답 헤더 설정에 제약이 있다. CSP를 HTML 메타 태그로 추가하려면 Flutter 부트스트랩, CanvasKit, WASM, 인라인 스크립트, 음원과 이미지 로딩이 깨지지 않는지 실제 브라우저에서 먼저 검증해야 한다.

보안 헤더를 필수 요구사항으로 올릴 경우 사용자 지정 헤더를 지원하는 정적 호스팅 또는 CDN으로 이전하는 방법을 검토한다.

## robots.txt와 검색 노출

현재 다음 파일은 배포되어 있지 않다.

- `robots.txt`
- `sitemap.xml`
- `.well-known/security.txt`

`robots.txt`는 검색엔진 크롤러에 대한 요청이며 접근 통제나 해킹 방지 장치가 아니다. 현재 서비스가 공개 데모 웹게임이므로 반드시 추가할 필요는 없다.

검색 노출을 원하지 않으면 `robots.txt`의 `Disallow`와 HTML의 `noindex`를 함께 검토한다. 이 설정을 추가해도 주소를 아는 사용자의 접근이나 파일 다운로드를 막을 수는 없다.

`security.txt`는 외부 보안 제보 창구를 운영할 때 추가하는 선택 항목이다.

## 배포 전 재점검 목록

1. `pages`에 반영할 커밋이 승인된 범위인지 확인한다.
2. 웹 빌드가 `WEB_DEMO=true`를 사용해 Easy 5판인지 확인한다.
3. 저장소와 Git 기록에 키·토큰·서명 파일이 없는지 확인한다.
4. 쿼리, 해시, 저장소 입력값이 허용 목록을 거치는지 확인한다.
5. `innerHTML`, `eval`, 동적 스크립트와 임의 URL 실행이 새로 추가되지 않았는지 확인한다.
6. `pubspec.lock` 기준 의존성 취약점을 다시 조회한다.
7. Flutter 전체 테스트와 웹 release 빌드를 통과시킨다.
8. GitHub Actions의 build와 deploy가 모두 성공했는지 확인한다.
9. 시크릿 창에서 첫 접속, BGM ON, BGM OFF, Easy 5판 표시를 확인한다.
10. 공개 응답이 HTTPS이고 예상한 최신 파일인지 확인한다.

## 운영 원칙

- 수정과 로컬 검증은 배포와 분리한다.
- 사용자가 명시적으로 배포를 요청한 경우에만 `pages`를 푸시한다.
- `main`은 앱 개발 기준을 유지하고 `pages`는 웹 데모 스냅샷으로 사용한다.
- 웹 코드와 에셋에는 비밀정보를 넣지 않는다.
- 서버 기능을 추가하면 이 문서를 정적 웹 기준에서 서버 포함 위협 모델로 개정한다.
