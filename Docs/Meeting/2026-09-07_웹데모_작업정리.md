# 2026-09-07 웹 데모 작업 정리

## 1. 목적

최근 진행한 웹 데모의 BGM 입력 문제, 체험판 분기, 마지막 판 안내 모달, 배포 및 보안 검증 내용을 한 문서에 정리한다. 완료된 구현과 아직 보완해야 할 항목을 구분해 이후 변경 시 기준으로 사용한다.

## 2. 브랜치와 배포 기준

| 대상 | 브랜치 | 용도 | 체험판 판수 |
| --- | --- | --- | --- |
| 앱 개발 | `main` | Google Play 앱 및 앱 관련 코드 개발 | Easy 10판 |
| 웹 데모 | `pages` | 웹 전용 코드와 GitHub Pages 공개 데모 | Easy 5판 |

- 웹 데모는 빌드 시 `--dart-define=WEB_DEMO=true`를 사용한다.
- `pages`에 푸시되면 `.github/workflows/deploy-pages.yml`이 자동 실행된다.
- `main` 푸시만으로는 Pages 배포가 실행되지 않는다.
- 배포 워크플로는 저장소 기본 `GITHUB_TOKEN`을 사용하므로 별도 개인 토큰이 필요하지 않다.
- 웹 전용 BGM 게이트, 웹 데모 분기 및 Pages 배포 변경은 `main`이 아니라 `pages`의 소유 범위다.
- 아직 배포하면 안 되는 웹 변경은 `pages`에 바로 푸시하지 않고 `web-demo-next` 같은 별도 원격 작업 브랜치에 보존한다.
- 사용자가 배포를 명시적으로 지시했을 때만 검증된 웹 작업 커밋을 `pages`에 반영한다.

## 3. 구현 완료 사항

### 3.1 웹 데모와 Play 체험판 판수 분리

- `GameBalance.isWebDemo`가 `WEB_DEMO` 컴파일 환경값을 읽는다.
- 웹 데모는 Easy 5판까지만 제공한다.
- Google Play 체험판은 Easy 10판까지 제공한다.
- Normal과 Hard는 체험판에서 노출하지 않는다.

### 3.2 웹 BGM 입력과 생명주기 보완

- 첫 진입 시 사용자의 명시적인 `BGM ON` 입력으로 타이틀 BGM을 시작한다.
- `BGM OFF`는 포인터 다운 시점에 비활성화 및 정지 처리를 먼저 수행한다.
- 웹 첫 진입에서 `BGM OFF`를 선택하면 SFX도 즉시 비활성화하고 저장한다.
- 앱 전체를 대상으로 하던 웹 오디오 자동 해제 입력은 제거했다.
- 비동기 환경설정 로드가 사용자가 방금 선택한 웹 BGM 상태를 뒤늦게 덮어쓰지 않도록 분리했다.
- 웹 HTML 오디오 리소스는 미리 로드한다.

### 3.3 웹 BGM 게이트 UI 보완

- 게이트 배경은 `Color(0x9907152F)`의 60% 반투명 색상으로, 뒤쪽 스플래시 콘텐츠가 보인다.
- 게이트가 전체 화면 포인터 입력을 흡수해 뒤쪽 콘텐츠가 눌리지 않게 했다.
- `BGM ON`과 `BGM OFF` 텍스트의 장식선을 강제로 제거하고 장식 색상도 투명 처리했다.
- 게이트 UI를 `splash_screen.dart`에서 `web_audio_gate.dart`로 분리해 단독 검증할 수 있게 했다.

### 3.4 마지막 체험판 안내 모달

- 마지막 체험판 스테이지 완료 후 Google Play 안내 모달을 한 번만 표시한다.
- Play 체험판에서는 10판, 웹 데모에서는 5판 완료가 표시 조건이다.
- 닫기 또는 스토어 이동 선택 후 확인 상태를 저장해 다시 표시하지 않는다.
- Google Play 패키지는 `com.tychespark.starlightsudoku`로 연결한다.
- 자동 테스트에서는 URL과 패키지 값까지만 확인하며 외부 스토어를 실제로 열지는 않는다.

### 3.5 회귀 방지 하네스

다음 테스트를 Pages 배포 전에 자동 실행한다.

- `test/web_bgm_contract_test.dart`
- `test/web_audio_gate_harness_test.dart`
- `test/trial_end_modal_harness_test.dart`

검증 범위는 BGM 시작·정지 분기, 게이트의 전체 화면 차단과 불투명 배경, 텍스트 장식 제거, 웹 5판/Play 10판의 마지막 판 모달 1회 노출이다.

### 3.6 웹 보안 점검

상세 결과는 `Docs/Security/2026-09-07_웹데모_보안점검.md`에 기록했다.

- 정적 Flutter 웹 앱이며 별도 백엔드, 데이터베이스, 입력 폼은 없다.
- 저장소와 빌드 대상에서 노출된 비밀값 및 명시적인 스크립트 삽입 경로는 발견되지 않았다.
- 의존성 87개를 OSV 기준으로 확인했으며 알려진 취약점은 0건이었다.
- GitHub Pages의 HTTPS와 HSTS를 사용한다.
- `robots.txt`와 `security.txt`는 현재 없다. 검색 랜딩이 아닌 게임 데모이므로 즉시 필수 사항은 아니며 필요할 때 추가한다.
- GitHub Pages 제약으로 CSP 등 일부 응답 헤더를 직접 강제하기 어렵다는 한계가 있다.

## 5. 미완료 및 확인 필요 사항

### 5.1 전체 모달 UI 수정 도구

현재 UI 수정 도구는 요청한 “전체 모달 UI 편집”을 완성한 상태가 아니다.

- 설정 모달의 크레딧 항목을 길게 눌러야 진입할 수 있어 발견하기 어렵다.
- 모달 선택기와 실제 모달별 미리보기가 없다.
- 공통 값과 모달별 값을 구분해 적용할 수 없다.
- 여섯 개 `ParchmentModal` 사용 화면에는 일부 공통값이 반영되지만, 마을의 `AlertDialog`와 레벨 로딩 `Card`는 범위 밖이다.
- 일부 전역 폰트·버튼·화면 여백 값은 모달 밖 화면에도 영향을 주므로 현재 범위는 동시에 좁고 넓다.
- 웹에서는 값을 SharedPreferences에 보관하고 JSON을 복사할 수 있지만 소스 코드에 직접 반영하지는 못한다.

따라서 이 기능은 완료로 간주하지 않는다. 다음 작업에서 모달 목록, 실제 미리보기, 공통/개별 토큰, 적용·초기화·복사 흐름, 예외 다이얼로그 통합을 다시 설계해야 한다.

### 5.2 브라우저 실동작 확인

- VM 위젯 하네스와 릴리스 웹 빌드는 통과했다.
- 로컬 Chrome 전용 Flutter 테스트는 DDC/브라우저 실행이 장시간 정체되어 완료 결과를 얻지 못했다.
- 자동 테스트와 별도로 시크릿 창에서 첫 진입 `BGM ON`, 즉시 `BGM OFF`, 새로고침 없는 재생, 버튼 텍스트 장식선, 마지막 판 모달을 최종 육안·청음 확인해야 한다.

## 6. 변경 시 필수 점검

1. 앱 기본 빌드에서 Easy 10판인지 확인한다.
2. `WEB_DEMO=true` 빌드에서 Easy 5판인지 확인한다.
3. 웹 BGM 게이트 변경 시 세 하네스를 모두 실행한다.
4. `BGM OFF`가 포인터 다운 단계에서 오디오를 먼저 정지하는지 유지한다.
5. 게이트 배경 알파가 `99`이고 텍스트 장식이 `none`인지 유지한다.
6. `pages` 푸시 전 변경 범위를 확인한다. 푸시 후에는 자동 배포 결과와 공개 파일 해시를 확인한다.
7. UI 수정 도구는 전체 모달 범위가 확정되기 전까지 완료로 표시하지 않는다.
